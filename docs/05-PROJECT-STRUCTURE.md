# Murmur — Project Structure

The tree is decided here so it is not improvised per feature. A file that does not have an obvious home in this layout is a signal the design is drifting.

**Two files carry the architecture.** `registry/mod.rs` declares what the app
HAS; `ipc/factory.rs` is what every command passes THROUGH. A third,
`bootstrap.rs`, is the only place a concrete adapter is named — which is what
makes swapping an engine or adding a platform a change to one file and one
directory.

## 2. Where things go — the decision table

| If you are writing… | It goes in | Never in |
|---|---|---|
| A new feature's metadata | `registry/mod.rs` | scattered constants |
| Business logic | `ipc/commands/` or `pipeline/` | services, components |
| A SQL query | `services/` | commands, pipeline |
| A trait for something swappable | `ports/` | adapters |
| A third-party integration | `adapters/<name>/` | ports, services |
| A shared type | `types/` | inline in the module |
| A component used in 2+ routes | `components/global/` | duplicated per route |
| A component used in 1 route | `app/<route>/_components/` | `components/global/` |
| UI-only state | `stores/` | React context, prop drilling |
| Domain state | Rust, pushed as events | Zustand |
| A color, size, spring | `styles/tokens.css` | the component |

## 4. Module header — required on every file

Same format as the guardrail boilerplate, because it is what makes `grep -l` work and keeps context cost flat:

```rust
/**
 * SOURCE OF TRUTH KEYWORDS: SessionMachine, SessionState, TransitionError,
 *   CancelPending, Finalizing, transition, can_transition, SessionEvent
 * WHAT:  The finite state machine governing one recording session.
 * WHY:   Recording state lives in exactly one place so illegal states are
 *        unrepresentable and every transition is logged and persisted.
 * WHERE: Owned by session/actor.rs; driven by ipc/commands/session.rs and
 *        the hotkey handler; read by the pill via session:state-changed.
 */
``` 

5–10 specific keywords. The next agent greps for a symbol, gets a short file list, and reads only those files. Skipping this is what turns a clean codebase into one nobody can navigate.

## 5. Hard limits

- **A file over ~400 lines is doing two things.** Split it.
- **A function over ~50 lines** needs a reason.
- **`ports/` contains no logic** — traits and capability structs only.
- **`services/` functions take parameters and return rows.** No branching on business rules, no calling other services.
- **Nothing imports upward.** `services` never imports `ports`; `ports` never imports `adapters`; `adapters` never import `ipc`. CI enforces this — `src-tauri/src/layering.rs` fails `cargo test` on an upward import, and CI runs the suite on every push, so it fails the build rather than being caught in review.

  Three violations exist today and are recorded in `KNOWN_UPWARD_IMPORTS` in that file, with the reason for each. They are one problem in three places: `AppState`, `SessionContext` and the typed event structs all live in `ipc/` and are all needed by the domain, so `session/actor.rs`, `session/delivery.rs` and `adapters/events.rs` reach up for them. The fix is to move those types down to a layer both sides can see. The list is self-cleaning — fixing one fails the suite until its entry is deleted — and it exists so that a fourth violation cannot appear unnoticed.

  This paragraph replaced a claim that CI enforced the rule at a time when there was no CI at all and the rule was already being broken. A guardrail described in a document and absent from the build is worse than an acknowledged gap, because everyone downstream reasons as though it holds.
